# 航海日志差分约束负环考证

TypeScript + React + Vite 单页应用：逐行录入航海日志断言，求证差分约束系统中
是否存在**权重和小于零的有向简单环**（负环），并给出最短且可重复复核的矛盾链。

## 问题语义

每行一条断言 `(编号, u, v, c)`，语义为：

```
date(v) − date(u) ≤ c
```

即“事件 v 的日期至多比事件 u 晚 c”。把每条断言看作有向边 `u → v`（权重 c），
约束系统不自洽当且仅当图中存在负环：沿环把不等式相加，左端相消为 0，
右端之和却小于零，得到 `0 ≤ 负数` 的矛盾。

## 录入规则

| 规则 | 说明 |
| --- | --- |
| 断言编号 | 匹配 `[1-9][0-9]{0,5}`（1–999999，无前导零）；整批唯一，按整数数值比较 |
| 事件名 | 区分大小写，非空，可含空格（含首尾空格）与中文等任意 Unicode 字符，长度不限，完全按录入原样参与计算（不做任何裁剪或归一化；`" 靠港 "` 与 `"靠港"` 是两个不同事件） |
| 上界 c | 整数，范围 `-100000` 至 `100000` |
| 批次规模 | 1–60 个事件、1–240 条断言 |
| 非法行 | 任一非法行均阻止计算，并在该行就地标注错误；全空行忽略，部分填写的行视为非法 |

## 求证算法（`src/lib/solver.ts`）

1. **最小边数**：对 min-plus 邻接矩阵逐阶求幂 `M^k`，首个使对角线出现负值的
   `k` 即负环的最小边数——边数最少的负闭途径必为简单环（否则可拆出更短的
   负闭途径，矛盾），故此时所有长度为 `k` 的负闭途径都是简单环。
2. **多项式构造（不枚举候选）**：精确步数幂 `P_t = M^t` 同时是可行性预言机：
   沿当前前缀走到 `x`、累计权重 `w`、还差 `t` 步时，接上出边 `e = x→y` 后能否
   完成负环，等价于 `w + e.c + P[t-1][y][s] < 0`。该判定是**精确**的而非松驰
   下界——长度为 `k` 的负闭途径必为简单环，预言机给出的最优完成途径不会重复
   事件。先按编号升序找到第一条能成环的边（即最优环上的最小编号边、环起点），
   再逐步贪心选择仍可完成负环的最小编号出边，总复杂度 `O(n⁴ + k·m)`。
3. **规范化与取舍**：贪心构造出的环以最小断言编号开头（保持原方向，禁止反转），
   且每一步都取可行的最小编号边，故其编号整数序列在所有边数最少的负环中字典序
   最小。编号整批唯一，故最小者唯一——平行边、自环、多环并存时结果稳定，与
   输入行序无关。

页面按环序逐条展示不等式 `date(v) − date(u) ≤ c`、累计和，以及“总和小于零”
的矛盾结论；无负环时只显示“约束相容”，不编造任何具体日期。

## 单条断言修订预演（`src/lib/tighten.ts`）

考证员确认一批日志相容后，常想收紧某条断言的日期上界。相容结论旁的预演面板
支持：选择一条现有断言，输入范围内（`-100000` 至 `100000`）且不大于原值的
新 c，**不改动录入表**地预演收紧后果。

**临界值**：排除被修订边 `e = (u, v, c)` 后，求结束事件 v 回到起始事件 u 的
最小权重路径，设其总权重为 `d`。修订后若产生负环，该环必含拟议边（其余断言
原本相容），环的其余部分恰是一条 v→u 路径，故：

- `c' ≥ -d` ⟺ 修订后仍相容（含等号：和为零不成负环）；
- `c' < -d` ⟺ 产生负环（拟议边与最小权重返回路径即拼成一条）。

临界值即 `-d`。若排除该边后 v 无法回到 u，则无论如何收紧都不会闭环，
明确标为**无有限临界值**。返回路径若有多条，依次按 **总权重 → 边数 →
编号整数序列字典序** 取唯一证明链（边数关键字保证路径简单，零权回路被
排除；编号整批唯一，故结果与输入行序无关）。临界值两侧的相容性判断与
负环求证（`solver.ts`）结果一致，由随机对照测试保证。

**交互**：判为安全时可一键写回该行并清除旧结论（写回后可再次考证）；
判为越界时展示由拟议断言与返回路径组成的逐步累计矛盾链，且禁止写回。
录入表任何变化或删除目标行会立即作废预演，并在原位置给出作废反馈。

## 本地开发

```bash
npm install
npm run dev          # 开发服务器
npm run test:unit    # Vitest 单元测试（解析 + 求解器 + 随机对照）
npm run build        # 类型检查 + 产物构建
npx playwright install chromium   # 首次运行 e2e 前安装浏览器
npm run test:e2e     # Playwright 端到端测试（自动启动 preview 服务器）
npm run verify       # 一次性全量校验：build + 单元 + e2e
```

## Docker Compose

```bash
docker compose up --build web        # 启动单页应用，默认 http://localhost:8080
WEB_PORT=3000 docker compose up web  # WEB_PORT 覆盖宿主端口
docker compose run --rm verify       # 一次性校验服务：跑完测试即退出
```

- `web`：多阶段构建，nginx 托管 `dist/`，宿主端口由 `WEB_PORT`（默认 8080）映射到容器 80。
- `verify`：基于官方 Playwright 镜像（浏览器与 `@playwright/test` 版本对齐），
  在容器内执行 `npm run verify`（构建 + Vitest + Playwright），属一次性服务。

## 项目结构

```
src/
  lib/
    types.ts        # 断言、见证、结论类型
    parse.ts        # 逐行与整批校验（就地标错）
    solver.ts       # 负环求证：最小边数 + 步数幂可行性预言机贪心构造 + 字典序
    tighten.ts      # 修订预演：排除被修订边求最小权重返回路径 + 临界值 + 矛盾链
    *.test.ts       # Vitest 单元测试（含随机图对照暴力枚举）
  components/
    ResultPanel.tsx  # 结论展示：环序不等式、累计和、总和小于零 / 约束相容
    TightenPanel.tsx # 修订预演面板：临界值、安全写回 / 越界矛盾链
  App.tsx           # 录入表单与交互
e2e/
  app.spec.ts       # Playwright：录入与求证全链路
  tighten.spec.ts   # Playwright：修订预演全链路（临界值、写回、作废反馈）
Dockerfile          # web / verify 双目标
docker-compose.yml  # web（WEB_PORT 可覆盖）+ verify 一次性服务
```
